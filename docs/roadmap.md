# 后续开发路线

## 第一阶段：工程基础（本次）

- pnpm workspace、React 管理界面、NestJS 基础、Swagger、健康检查。
- 环境变量、异常响应、代码规范、类型检查和基础行为测试。
- PostgreSQL Compose、Prisma 访问层与用户/组织/成员初始模型。
- 登录、工单、成员、设置明确作为预览和开发中页面。

## 第二阶段：认证与组织边界

先启动真实 PostgreSQL 并验证初始迁移，再实现密码摘要、登录和 JWT 身份认证。建立全局 User 与组织 Membership 的关联，提供当前用户、组织创建/选择和成员基础能力。组织创建和 OWNER Membership 创建必须在同一事务中完成。

建立认证 Guard、租户上下文、成员资格检查和企业级角色 Guard。每个企业资源操作必须校验 organizationId 与 Membership，前端接入真实登录、认证状态与退出。

验收重点：无凭据 401、权限不足 403、跨租户读写失败、重复成员受唯一约束保护、事务失败回滚。确定最后一个 OWNER 的保护规则。Redis 只在出现验证码、限流或令牌撤销需求时引入。

## 第三阶段：工单核心闭环

实现 Ticket 模型与租户复合外键、创建、列表、详情、指派、状态流转、评论。接入前端表格、筛选和分页，定义 AGENT 与 MEMBER 的具体业务权限。创建工单、编号分配和状态转换通过事务保障一致性。

验收重点：跨企业成员不能被指派；非法状态流转被拒绝；筛选分页稳定；前端正确区分加载、空数据、失败与成功。

## 第四阶段：审计、统计与可靠性

加入关键操作审计、企业看板真实统计、必要的 Redis 缓存与限流。补充结构化日志、请求标识、数据库索引与端到端租户隔离测试。审计数据必须含租户与操作者，禁止写入密码和令牌。

## 第五阶段：部署与求职展示

制作前后端镜像、反向代理、CI 检查与迁移发布流程，配置 HTTPS、生产密钥、备份与恢复。补充架构讲解、演示账号授权方式和可复现演示场景。完整证明认证、多租户和 RBAC，而不是仅展示按钮。

本次完成第一阶段后停止。Docker 缺失导致的数据库验证应在第二阶段开始前补齐，不自动扩展当前阶段。
